# CLAUDE.md

- **Scope**: stay inside this checkout. Confine searches and reads to this repository.
- **Check**: run `bun run check` after each batch of edits. It generates the TanStack route tree, typechecks with `bun check -b`, lints with `bun lint`, and runs `scripts/check-jsx-double-read.ts`, and checks formatting with `bun fmt --check`. Lint and format read the oxc configs (`.oxlintrc.json`, `.oxfmtrc.json`). Use `bun check` for types, never `tsc` or `bunx tsc`.
- **Dev URLs**: connect to `https://fenchem.localhost` with `ignoreHTTPSErrors: true`. Do not resolve to raw localhost ports. Ad-hoc browser scripts require system Chrome (`channel: "chrome"`).
- **OOS1 subpages**: view components live in `apps/web/src/components/prototype/variant-oos1/`: `about-view.tsx`, `insights-view.tsx`, `news-view.tsx`, `rd-view.tsx`, and `contact-view.tsx`.
- **Prototype labs**: verify `/prototypes/*` with `bun run test:prototypes`. It runs the typed specs in `apps/web/e2e/prototypes/` in system Chrome against this checkout's portless dev server. Add a lab's interaction checks there as web-first assertions. `test:e2e` serves a production build, where prototype routes return not-found. Verify motion and scroll headlessly; the Browser pane throttles animation frames while hidden.
- **Hydration**: after a change that renders, run `bun run test:hydration` in `apps/web`. It loads every variant, oos1 page, and lab in parallel and fails on hydration warnings, console errors, and 5xx responses. Specs wait on `html[data-hydrated]`, which `HydrationMark` sets after the page's `<Loading>` boundary settles.
- **Solid diagnostics**: Solid 2 explains its dev warning codes, such as `STRICT_READ_UNTRACKED`, and hydration-id skew in `node_modules/solid-js/skills/reactivity-diagnostics/SKILL.md`. Read the matching section before you fix a Solid warning or a hydration mismatch.
- **Visual checks**: verify a change that could move pixels with `bun run ui`, or delegate the run to the `ui-verifier` agent with the intended change. Before a refactor, run `bun run ui snap <page>`; after it, `bun run ui diff` compares every snapped baseline. Compare a new variant against its parent with `bun run ui diff <before> <after>`. Pages are dev-server paths such as `"/?variant=oos1&page=about"`. `bun run ui --help` lists the commands, and `--dry-run` prints what a command would render.
